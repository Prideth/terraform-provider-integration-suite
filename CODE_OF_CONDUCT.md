# Project Code of Conduct

## Purpose

This repository is a technical open-source project focused on the Terraform
Provider for SAP Integration Suite.

Project communication should remain professional, factual, technically
relevant, and focused on improving the software.

This project is not a forum for political campaigning, ideological
activism, party politics, culture-war discussions, or unrelated social and
political debates.

Political or regulatory topics may only be discussed when they are directly
relevant to the technical, legal, security, licensing, or operational
requirements of the project. In those cases, discussion must remain factual
and limited to the matter required for the project.

No political or ideological position is considered part of the project's
identity.

## Expected Behavior

Contributors are expected to:

- Treat other contributors professionally and respectfully.
- Discuss technical ideas based on evidence, documentation, reproducible
  behavior, and engineering trade-offs.
- Give and receive constructive technical feedback.
- Separate criticism of code or technical decisions from criticism of
  individuals.
- Keep issues, pull requests, reviews, discussions, and documentation
  relevant to the project.
- Disclose technical limitations and uncertainty rather than presenting
  assumptions as facts.
- Respect privacy and confidential information.
- Follow applicable licenses, security requirements, and contribution
  rules.

Technical disagreement is normal and welcome.

Strong disagreement about an implementation, architecture, API
interpretation, or engineering decision is not itself inappropriate
behavior as long as discussion remains professional and relevant.

## Political and Ideological Neutrality

Project spaces must not be used for:

- Political campaigning.
- Party-political advocacy.
- Promotion of political or ideological movements.
- Political slogans or messaging unrelated to the software.
- Attempts to associate the project with a political position.
- Culture-war discussions.
- Political arguments unrelated to a concrete technical or legal
  requirement.
- Requiring contributors to endorse political, ideological, or social
  positions unrelated to their contribution.
- Adding political messaging to source code, documentation, examples,
  workflow names, issue templates, release notes, project metadata, or
  other project materials.

These rules apply equally regardless of political or ideological
direction.

When terminology with political implications is genuinely required for
legal, regulatory, compliance, or technical documentation, use neutral and
precise factual language.

For example, project documentation should describe the relevant law,
regulation, technical requirement, or governance mechanism directly rather
than introducing unrelated political slogans or advocacy.

## Unacceptable Behavior

The following behavior is not acceptable:

- Harassment, intimidation, or threats.
- Personal attacks or deliberately insulting communication.
- Discriminatory treatment of contributors based on personal
  characteristics.
- Publishing another person's private information without permission.
- Deliberate disruption of technical discussions.
- Repeated bad-faith arguments after a technical decision has been
  documented and explained.
- Spam or unrelated promotional content.
- Sexualized content or behavior unrelated to legitimate technical
  discussion.
- Using project communication channels primarily for political or
  ideological disputes.

Criticism of code, APIs, architecture, design decisions, documentation, or
technical proposals is permitted and encouraged when relevant and
constructive.

## Technical Decision Making

Technical decisions should primarily be based on:

- Official specifications and documentation.
- Reproducible technical evidence.
- Security.
- Correctness.
- Compatibility.
- Maintainability.
- Performance.
- Terraform semantics.
- SAP API supportability.
- User impact.
- Long-term project sustainability.

A contributor's political, ideological, or personal views are irrelevant
to the technical merits of a contribution.

## Scope

This Code of Conduct applies to project-controlled spaces, including:

- Issues
- Pull requests
- Code reviews
- Discussions
- Repository documentation
- Project-related communication channels
- Release discussions

Conduct outside those spaces is generally outside the scope of this
project unless it directly involves abuse, impersonation, disclosure of
confidential project information, or other behavior materially affecting
the project.

## Enforcement

Project maintainers are responsible for interpreting and enforcing these
rules.

Depending on severity and context, maintainers may:

- Ask that a discussion return to the technical topic.
- Remove or edit off-topic content where the platform permits it.
- Close an issue or discussion.
- Reject a contribution.
- Restrict participation.
- Report serious abuse through the relevant hosting platform.

Enforcement decisions should be based on behavior within the scope of the
project rather than on a contributor's unrelated political or personal
beliefs.

## Project Principle

Keep the project technical.

Contribute code, documentation, tests, bug reports, architecture, and
constructive engineering discussion.

Political and ideological advocacy belongs elsewhere.
